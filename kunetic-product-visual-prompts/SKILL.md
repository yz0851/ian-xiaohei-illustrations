# KUNETIC 产品页视觉提示词

## 核心定位

为 KUNETIC 产品详情页设计配图方案和完整生图提示词。

保留原版 Skill 的核心方法：先理解内容，再找视觉重点，再选择构图，最后输出 Shot List 和单张提示词。不同之处是，本 Skill 读取指定 Product Lab 产品目录，不读取文章，也不调用图像模型。

Product Lab 决定：图片数量、页面槽位、目标比例、基本职责、批准文案、事实边界、文件名和 Alt。

本 Skill 决定：视觉模式、构图、镜头、场景、光线、信息层级和完整提示词。

即使用户说“生成图片、出图、制作主图”，也只输出可以直接交给外部生图工具的完整提示词，不调用任何生图或图片编辑工具。

## 先读这些参考

按任务需要读取，不要一次塞满上下文：

- `references/product-lab-input-contract.md`：槽位匹配、比例、文案、参考图和交接边界。
- `references/style-dna.md`：视觉模式、颜色、字体和真实场景规则。
- `references/product-fidelity.md`：真实产品和内部结构边界。
- `references/composition-patterns.md`：产品页构图类型和反重复规则。
- `references/prompt-template.md`：简洁的单张提示词模板。
- `references/qa-checklist.md`：交付前检查和迭代规则。
- `assets/style-calibration/index.md`：分类视觉校准索引。每个图片任务先读索引，再选择并实际打开最相关的 1–3 张参考图；不得只看文件名就声称已经参考。

## 调用前提

用户应明确指定：

- Product Lab 仓库；
- 当前产品目录。

当用户明确要求“使用仓库中最新发布的产品”时，可以通过提交记录定位最近正式发布的产品目录，但必须在输出中说明所选目录。不要把多个产品目录混在一起。

典型调用：

```text
Use $kunetic-product-visual-prompts

请读取：
yz0851/kunetic-product-lab
products/YYYY-M-D-{stable-product-id}/

根据已批准的事实、文案、Layout 和图片框架，
设计产品页配图并输出完整提示词。不要生成图片。
```

## 工作流

### 1. 消化产品页资料

按 `product-lab-input-contract.md` 分层读取，先确认：

- 产品身份和主要采购者；
- 页面主叙事和核心卖点；
- 图片总数、页面槽位、目标比例和基本职责；
- 已批准参数、文字和技术边界；
- 当前任务能否实际访问真实产品参考图。

不要重新从原始 PDF 推翻已批准事实。

### 2. 先匹配页面槽位并锁定比例

用户只说“产品主图、场景图、拓扑图、工厂图”等类型时，不能默认全部映射到 Hero。

优先匹配：

- 产品主图 → Hero Product Identity；
- 参数图 → Hero Core Specifications；
- 场景图 / 应用图 → Applications Poster；只有用户明确说 Hero 场景图时才匹配 Hero Applications；
- 拓扑图 / 系统图 → Overview System Diagram；只有用户明确说 Hero 拓扑图时才匹配 Hero Topology；
- 工厂图 / OEM 图 → Project Configuration / OEM Poster；
- 液冷图 / 户外图 → Outdoor and Thermal Operation；
- PCS 架构图 → Cluster-Level Power Conversion。

输出提示词前必须先列出：

```text
图片要求 → 匹配槽位 → 比例 / 尺寸 → 比例来源
```

设计新图片时，比例优先级为：

1. 用户当前明确指定；
2. 已批准 `image-production-plan.md`；
3. 已批准 `layout-design-brief.md`；
4. 页面组件默认比例；
5. 历史媒体实际尺寸。

替换现有图片时，用户指定之后优先参考现有媒体实际尺寸。发现设计比例与历史媒体尺寸冲突时，必须显式说明，不得静默选择。

### 3. 提取对应槽位文案并检查参考图

每张图匹配槽位后，依次读取：

1. 图片计划中的 `Image text`；
2. 对应区块的批准标题；
3. Eyebrow、Subtitle 或 Intro；
4. 批准的设备 Label 和参数。

只有 Product Lab 明确写 `Image text: None`、用户明确要求无文字，或图片职责明确为纯产品展示时，才默认无新增文字。

检查产品图可用性：

- 当前对话中有可见真实产品图：直接使用“参考图1产品”或“提取图1产品”；
- 仓库中有可读取真实图片：读取并编号后使用；
- 仓库只有文件名、Manifest 或本地路径：不得假装看到了图片，必须说明提示词需要用户把真实产品图上传为参考图1。

产品外观约束采用“图片优先、文字最小化”：

```text
参考图1中的真实产品制作，保持图1产品外观不变，不重新设计产品。
```

不要默认枚举门板、门缝、把手、铰链、散热口、接口、底座或材质。只有某个清晰可见结构对当前任务非常重要，或模型曾经在该结构上出错时，才增加一条针对性约束。

### 4. 选择并实际查看视觉校准图

先读取 `assets/style-calibration/index.md`，根据当前图片职责选择最接近的类别：

- 产品主图 → `product-hero/`；
- 产品海报 → `product-poster/`；
- 独立应用场景或多场景图片区块 → `real-application/`；
- 客户人物与真实现场 → `customer-real-scene/`；
- 系统拓扑和能源流 → `topology/`；
- 工厂、生产、OEM / ODM → `factory-oem/`；
- 功能、集成、安全、部件或技术卖点表达 → `feature-visualization/`；
- 尺寸、重量、安装和部署 → `deployment-scale/`；
- 参数、标题、标签和信息层级 → `typography-layout/`。

每个图片任务通常只选择 1–3 张参考图：

1. 优先选择最接近类别中的 `Primary`；
2. `Secondary` 用于补充某个更窄的构图模式；
3. `Caution` 只有在其视觉价值明确且风险边界可控时才使用；
4. 跨类别参考只用于补充一个明显不同的设计元素，不得为了“多参考”而混用风格。

必须实际打开所选图片后，才能说明借鉴了哪些视觉特征。图片无法打开时，应明确写“未完成视觉查看”，不得依据文件名猜测内容。

视觉校准图只允许影响：

- 构图与留白；
- 产品占比和镜头距离；
- 场景质感；
- 标题、参数和标签层级；
- 拓扑节点和箭头组织；
- 字体、品牌色和注释方式。

不得据此补充或确认产品外观、参数、认证、客户项目、工厂能力、内部结构或技术功能。

应用场景需要区分“整体版式”和“场景质感”：多场景应用图可以采用产品主导的合成式海报布局，但其中每个场景分图仍应保持普通手机现场照片的自然光、普通视角、真实尺度和轻微不完美感。不得把整张合成海报描述成一张真实项目现场照片，也不得把其中任何场景当作真实 KUNETIC 项目证据。

### 5. 搜索行业与设计参考

除以下情况外，产品主图、应用场景图、拓扑图、工厂图、功能概念图和新构图方向都必须先搜索相关行业与设计案例：

- 用户要求严格复刻现有图；
- 用户在当前任务中已经明确指定某张或某类设计参考；
- 仅修改少量文字、尺寸或检查提示词。

内置 `style-calibration` 图库不自动等同于用户在当前任务中明确提供的设计参考，不得仅因图库存在就跳过行业搜索。

优先研究国际储能与工业设备品牌、真实项目摄影、产品页、系统拓扑和工业设计案例。搜索只用于：

- 构图与留白；
- 产品在画面中的比例；
- 标题和参数层级；
- 场景视角与摄影距离；
- 拓扑节点与箭头组织；
- 字体和品牌色搭配。

不得用搜索结果补充 KUNETIC 的产品外观、参数、内部结构、认证、客户、工厂规模、产能或真实项目。

在 Shot List 前简要输出：

- 实际打开的 1–3 张视觉校准图、借鉴点和不复制内容；
- 2–4 个行业与设计参考方向：来源类型、借鉴点和明确不复制的内容。

如果当前环境无法打开视觉校准图或无法搜索，必须分别说明未完成的部分，不得假装完成。

### 6. 形成 Shot List

Shot List 必须完全对应已匹配的 Product Lab 槽位，不得擅自增删图片。

每张图写清楚：

- 页面位置与基本职责；
- 目标比例和比例来源；
- 对应批准文案；
- 主要视觉模式；
- 创意自由度：`strict / guided / exploratory`；
- 产品参考图可用状态；
- 采用的视觉校准图及具体借鉴点；
- 建议构图；
- 必须保留和禁止出现。

用户只要求“先规划”时，到 Shot List 为止。用户要求完整方案时，不等待二次确认，继续输出提示词。

### 7. 单张提示词设计

每张图单独输出一份完整提示词，一张图只承担一个主要任务。

提示词应包含：

- 图片用途、匹配槽位和准确比例；
- 简洁的真实产品参考语句；
- 核心表达；
- 构图、镜头和产品位置；
- 背景、场景、光线和质感；
- 准确英文文案、标签和字体；
- 与当前图片直接相关的少量禁止项。

产品主体描述通常控制在 1–2 句话。禁止项通常控制在 5–8 项，不机械复制通用长清单。

凡涉及真实项目、安装、仓库、运输、应用或工厂场景，必须以：

```text
一张由iphone6s随意拍摄的真实照片……
```

作为摄影风格开头，再描述具体环境。

多场景应用海报可以采用合成式整体布局，但每个场景分图仍应延续上述普通手机实拍质感；不要把合成版面写成一张真实项目照片。

### 8. 检查与交付

按 `qa-checklist.md` 检查槽位、比例、文案、产品参考图、视觉校准图、行业搜索、产品约束和事实边界。

默认交付顺序：

1. 产品目录与资料状态；
2. 槽位和比例匹配结果；
3. 视觉校准图与行业设计参考摘要；
4. Shot List；
5. 每张图的完整提示词；
6. 可选优化建议；
7. QA 结果。

用户明确要求保存时，可写入当前产品目录：

```text
content/visual-prompt-pack.md
```

不要覆盖 `content/image-production-plan.md`，不要修改事实、文案、Layout、状态文件或发布数据。

## 兼容旧版 Product Lab 图片计划

旧版 `image-production-plan.md` 可能包含详细场景、镜头或完整提示词。

以下内容仍是硬约束：

- 图片数量；
- 页面位置和 Block ID；
- 目标比例；
- 基本职责；
- 已批准事实和文字；
- 必须保留与禁止项；
- 文件名、Alt 和派生关系。

已有的具体构图、背景、镜头和完整提示词，在用户未明确批准为固定方案时，只作为历史设计参考，本 Skill 可以重新设计。

## 输出口径

输出要简洁、具体、可执行。不要用大量文字描述参考图本身已经能够表达的产品外观。

发现图片框架不合理时：

- 正式方案仍按当前框架输出；
- 可选优化建议单独说明问题、替代方向和是否需要返回 Product Lab；
- 不直接修改 Product Lab。
